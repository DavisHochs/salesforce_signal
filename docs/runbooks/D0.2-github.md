# D0.2 — GitHub repo, branch protection, Actions secrets

Owner: Davis. Repo: https://github.com/DavisHochs/salesforce_signal (created).

## 1. First push

Push the Phase 0 scaffold to `main` so CI runs once. The check names
appear only after the first run.

## 2. Branch protection on `main`

GitHub → Settings → Branches → Add rule (or Rulesets) for `main`:

- [ ] Require a pull request before merging (approvals: 0 is fine for a solo project)
- [ ] Require status checks to pass: `Lint and AUTO tests`, `Secret scan (gitleaks)`
- [ ] Block force pushes and deletions

## 3. Actions secrets

Phase 0 CI needs **no secrets**: AUTO tests use mocks, and gitleaks uses the built-in
`GITHUB_TOKEN` (no `GITLEAKS_LICENSE` needed for a personal-account repo).

Add later, only when a CI job needs a live service (none planned; AUTO-LIVE runs locally):
Settings → Secrets and variables → Actions.

## 4. Optional repo settings

- [ ] Settings → Code security → turn on secret scanning and push protection
- [ ] Dependabot alerts on

## Done when

- [ ] CI green on `main` (this is T0.1)
- [ ] Branch protection active with both checks required
